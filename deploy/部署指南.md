# 医院医保专栏 · Ubuntu 内网部署指南

本项目是**纯 Node.js 实现、零外部依赖**的内部网站。本指南帮助你在内网稳定运行，并实现开机自启、防火墙放行、数据可备份。提供两种路线：**Docker 容器**（跨平台、隔离好、一条命令起，推荐已用 Docker 的环境，见文末「附：Docker 部署」）与 **Ubuntu 原生 systemd**（见下方方式一~三）。

> 适用前提：你已在本机（开发机）拿到完整项目文件夹（含 `server.js`、`public/`、`data/`、`package.json`、`deploy/`）。

---

## 一、整体架构（部署后）

```
内网用户浏览器
      │  http://<服务器IP>:51888/
      ▼
  Ubuntu 服务器
   ├─ Node.js 进程  (server.js，监听 0.0.0.0:51888)
   ├─ systemd 服务  (medical-portal，开机自启 + 崩溃重启)
   ├─ 数据目录 /opt/medical-portal/data  (db.json + uploads/)
   └─ [可选] Nginx 反代 + HTTPS（统一入口/证书）
```

要点：
- 代码用 `__dirname` + `path.join`，**无 Windows 硬编码路径**，跨平台直接跑。
- `server.listen(PORT)` 默认绑定**所有网卡**，所以内网其他机器可直接访问（只要防火墙放行）。
- 所有业务数据（通知、文件元数据、上传文件）都在 `data/` 目录，备份它即可。

## 二、方式一：一键脚本部署（推荐）

1. **把整个项目文件夹传到服务器**（任选一种）：

   ```bash
   # 开发机上，用 scp 把整个目录推到服务器（假设服务器 192.168.1.10）
   scp -r /path/to/2026-10-12-21-05-01 user@192.168.1.10:/tmp/medical-portal

   # 或先用 U 盘/内网共享拷过去也行
   ```

2. **登录服务器，运行脚本**：

   ```bash
   ssh user@192.168.1.10
   sudo bash /tmp/medical-portal/deploy/setup.sh
   ```

   脚本会自动完成：安装 Node.js 20 LTS → 建专用运行用户 → 拷贝到 `/opt/medical-portal` → 写 systemd 服务 → 启动 → 放行防火墙。

3. **记下输出的管理员密码**（脚本随机生成，或你用 `MEDICAL_ADMIN_PASSWORD=xxxx` 指定）。

4. **浏览器访问**：

   - 前台：`http://<服务器IP>:51888/`
   - 后台：`http://<服务器IP>:51888/admin.html`

> 想自定义端口/密码？运行前先设环境变量：
> ```bash
> MEDICAL_PORT=8080 MEDICAL_ADMIN_PASSWORD='MyStrongPw123' sudo -E bash /tmp/medical-portal/deploy/setup.sh
> ```
> （`sudo -E` 才能把环境变量带进去；或直接在脚本里改默认值。）

## 三、方式二：手动部署（看清每一步）

适合你想完全掌控、或服务器已装好 Node 的情况。

```bash
# 1) 安装 Node.js（若已有 node ≥16 可跳过；推荐 20 LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs

# 2) 建专用用户（不让网站以 root 跑）
sudo useradd --system --no-create-home --shell /usr/sbin/nologin medical

# 3) 放代码
sudo mkdir -p /opt/medical-portal
sudo rsync -a --exclude='.workbuddy' /tmp/medical-portal/ /opt/medical-portal/
sudo chown -R medical:medical /opt/medical-portal
sudo chmod -R ug+rwX /opt/medical-portal/data

# 4) 写 systemd 服务（参考 deploy/medical-portal.service，记得改 ADMIN_PASSWORD）
sudo cp /tmp/medical-portal/deploy/medical-portal.service /etc/systemd/system/
sudo nano /etc/systemd/system/medical-portal.service   # 把 __CHANGE_ME__ 改成强密码

# 5) 启动
sudo systemctl daemon-reload
sudo systemctl enable --now medical-portal

# 6) 防火墙放行
sudo ufw allow 51888/tcp

# 7) 验证
sudo systemctl status medical-portal
curl -s http://127.0.0.1:51888/ | head -n 5
```

## 四、方式三：临时/测试（nohup，不推荐生产）

```bash
cd /opt/medical-portal
ADMIN_PASSWORD='临时密码' PORT=51888 node server.js > /tmp/medical.log 2>&1 &
```

好处是简单；坏处是**重启服务器不会自启、进程挂了不会自动拉起**。仅用于临时验证。

## 五、修改配置 / 改管理员密码

### 5.1 改后台密码（两种办法）

- **办法 A（最方便）**：登录后台 → 左侧「修改密码」表单 → 输入当前密码 + 新密码。
- **办法 B（改环境变量）**：编辑 systemd 服务里的 `ADMIN_PASSWORD`，再重启：

  ```bash
  sudo systemctl edit --full medical-portal   # 改 Environment=ADMIN_PASSWORD=...
  sudo systemctl restart medical-portal
  ```

> 注意：办法 B 写入的是**明文哈希前的值**，服务启动时会重新 sha256 哈希。后台表单改密同理。

### 5.2 改端口 / 站点名

编辑 systemd 服务的 `Environment=PORT=...` 与 `SITE_NAME=...`，`sudo systemctl daemon-reload && sudo systemctl restart medical-portal`，并记得 `sudo ufw allow 新端口/tcp`。

## 六、数据备份与迁移

**备份**（整个 `data/` 目录即可，含 `db.json` 与 `uploads/` 上传文件）：

```bash
sudo tar czf medical-data-$(date +%F).tar.gz -C /opt/medical-portal data
```

**迁移到另一台服务器**：
1. 在新服务器按「方式一/二」部署好（先不急着上传数据）。
2. 停服务：`sudo systemctl stop medical-portal`
3. 用备份覆盖新机器的 `/opt/medical-portal/data`，修正属主：`sudo chown -R medical:medical /opt/medical-portal/data`
4. 启服务：`sudo systemctl start medical-portal`

> 建议把 `DATA_DIR` 指向一块独立/大容量磁盘（如 `/data/medical`），避免系统盘占满。改法：systemd 服务里 `Environment=DATA_DIR=/data/medical`。

---

## 七、可选：Nginx 反向代理 + HTTPS（内网统一域名/证书）

如果内网有域名或统一 CA 证书，建议加一层 Nginx，好处：统一 80/443 入口、可做 HTTPS、限制上传体积、隐藏真实端口。

1. `sudo apt-get install -y nginx`
2. 把 `deploy/nginx-medical-portal.conf` 内容写好，放到 `/etc/nginx/sites-available/medical-portal`，软链到 `sites-enabled`，改里面的 `server_name` 与证书路径。
3. `sudo nginx -t && sudo systemctl reload nginx`
4. 此时用户访问 `http://med.internal.example.com/` 即可（Nginx 转发到本机 51888）。
5. 若只用 IP、不打算上 HTTPS，把 Nginx 配置里 `listen 80` 那段直接用即可，无需证书。

> 用了 Nginx 后，防火墙只需放行 80/443，51888 可只对 127.0.0.1 开放（在 systemd 里把端口改绑 `127.0.0.1:51888` 更安全，但本项目默认绑所有网卡，配合防火墙/内网隔离即可）。

## 八、升级 / 更新代码

以后你改了前台页面或 `server.js`，更新步骤：

```bash
# 1) 把新代码传到服务器（如 /tmp/medical-portal-new）
# 2) 停服务
sudo systemctl stop medical-portal
# 3) 覆盖代码（保留 data/，不要覆盖它！）
sudo rsync -a --exclude='data' --exclude='.workbuddy' /tmp/medical-portal-new/ /opt/medical-portal/
sudo chown -R medical:medical /opt/medical-portal
# 4) 重启
sudo systemctl start medical-portal
```

> 关键：**`rsync` 排除 `data`**，否则会覆盖掉线上已发布的数据和上传文件。

## 九、常见问题排查

| 现象 | 排查 |
|---|---|
| 浏览器打不开 | 服务器上先 `curl http://127.0.0.1:51888/` 确认本机能通；再查 `sudo ufw status` 是否放行端口；确认客户端与服务器在同一网段/VLAN |
| 后台登不上 | 确认密码是否正确（首次为安装时生成的随机密码或 `admin123`）；查日志 `sudo journalctl -u medical-portal -n 50` |
| 上传文件失败/大文件被拦 | 用了 Nginx 需 `client_max_body_size 200m`；未用 Nginx 则检查磁盘空间与 `data/uploads` 写权限 |
| 重启服务器后没自动起 | `sudo systemctl is-enabled medical-portal` 应为 `enabled`；否则 `sudo systemctl enable medical-portal` |
| 端口被占用 | `sudo ss -ltnp | grep 51888` 看是谁占用，改 `PORT` 或停掉冲突进程 |
| 日志查看 | `sudo journalctl -u medical-portal -f`（实时） |

## 十、安全建议（内网也不能忽视）

1. **改掉默认密码** `admin123`：安装时指定强密码，或装后立刻在后台改。
2. **专用低权限用户**运行（脚本已用 `medical` 系统用户，非 root）。
3. **网络隔离**：把 51888 限制在院内 VLAN/防火墙白名单，不要暴露到公网。
4. **定期备份** `data/` 目录（见第六节）。
5. **HTTPS**：若通过统一门户访问，建议走 Nginx + 内网 CA 证书，避免明文传输后台密码。
6. **上传目录**：`data/uploads` 由 Node 直接读，确保 Web 服务器（若用 Nginx）不要把该目录当作可执行脚本目录。

## 附：Docker 部署（已用 Docker 的环境，推荐）

容器化部署把运行环境、进程守护、数据持久化打包好，**不依赖宿主机的 Node 版本与 systemd**，跨平台一致。项目根目录已提供 `Dockerfile`、`docker-compose.yml`、`.env.example`、`.dockerignore`。

### A. 前置条件
- 服务器（Ubuntu 或其他 Linux）已安装 **Docker Engine** 与 **Docker Compose v2**（`docker compose` 子命令）。
  - Ubuntu 一键装：`curl -fsSL https://get.docker.com | sudo sh` 然后 `sudo usermod -aG docker $USER`（注销重登生效）。

### B. 部署步骤
```bash
# 1) 把整个项目文件夹传到服务器（如 /opt/medical-portal）
sudo mkdir -p /opt/medical-portal
sudo rsync -a --exclude='.workbuddy' --exclude='data' /本地项目/ /opt/medical-portal/

cd /opt/medical-portal

# 2) 准备环境变量（改管理密码）
cp .env.example .env
nano .env            # 把 ADMIN_PASSWORD 改成强密码

# 3) 构建并启动（后台运行）
docker compose up -d --build

# 4) 查看状态与健康
docker compose ps
docker compose logs -f        # Ctrl+C 退出日志
```

### C. 访问
- 前台：`http://<服务器IP>:51888/`
- 后台：`http://<服务器IP>:51888/admin.html`（密码为 .env 中设置的 `ADMIN_PASSWORD`）

### D. 常用运维命令
```bash
docker compose restart            # 重启
docker compose down               # 停止并移除容器（数据卷保留）
docker compose up -d --build      # 更新代码后重新构建
docker compose exec medical-portal sh   # 进容器排错
```

### E. 数据备份与迁移
- 数据在命名卷 `medical_data`（容器内 `/app/data`）。备份：
  ```bash
  docker run --rm -v medical-portal_medical_data:/data -v $PWD:/backup alpine \
    tar czf /backup/medical-data-$(date +%F).tar.gz -C /data .
  ```
  （卷名默认带 compose 项目前缀，可用 `docker volume ls` 确认实际名称。）
- 迁移到别的机器：在新机器 `docker compose up -d` 起服务后，把备份解压进同名卷即可。

### F. 进阶
- **改端口**：编辑 `docker-compose.yml` 的 `ports`，如 `"8080:51888"`（对外 8080）。
- **只监听本机 + Nginx 反代**：把 `ports` 改为 `"127.0.0.1:51888:51888"`，再用 `deploy/nginx-medical-portal.conf` 反代，配合 HTTPS。
- **大文件上传**：Nginx 反代需 `client_max_body_size 200m`；直连容器端口不受限。
- **升级代码**：本地改好 `server.js`/`public/` 后重新 `rsync` 到服务器，再 `docker compose up -d --build`。

### G. 注意事项
- 镜像已配置**健康检查**与**非 root 用户运行**，并 `restart: unless-stopped` 实现异常自愈。
- `server.js` 已显式 `listen(PORT,'0.0.0.0')`，确保容器端口映射可用（不影响本地 localhost 访问）。
- 默认密码 `admin123` 仅在未设 `ADMIN_PASSWORD` 时生效；**生产务必在 `.env` 中设置强密码**，或登录后台「修改密码」。

### H. 推送到私有镜像仓库（供多台服务器/同事拉取）

把镜像推到私有 registry 后，目标服务器**无需源码、无需 Dockerfile**，直接拉镜像运行，适合批量部署与离线环境。

#### 1) 在构建机（能连 registry、已装 Docker）上构建并推送
```bash
# 进入项目根目录
cd /path/to/medical-portal

# 设置仓库前缀（含末尾斜杠）与标签，然后执行脚本
REGISTRY=registry.example.com/medical/ TAG=1.0.0 ./deploy/build-and-push.sh
```
脚本会执行：`docker compose build` → `docker compose push`，最终镜像名为
`registry.example.com/medical/medical-portal:1.0.0`。
若不想用脚本，手动等价命令：
```bash
export REGISTRY=registry.example.com/medical/ TAG=1.0.0
docker compose build
docker compose push
```

#### 2) 登录私有仓库（首次/凭据失效时）
- **通用**：`docker login registry.example.com`（交互输入账号密码；Harbor/ACR/TCR 同理）。
- **脚本内自动登录**：传 `REGISTRY_USER` / `REGISTRY_PASS` 环境变量给 `build-and-push.sh`。
- **常见仓库 host 写法**：
  - 自建 Harbor：`registry.example.com/medical/`（login 用 `registry.example.com`）
  - 阿里云 ACR：`registry.cn-hangzhou.aliyuncs.com/你的命名空间/`
  - 腾讯云 TCR：`ccr.ccs.tencentyun.com/你的命名空间/`
  - Docker Hub 私有：`你的用户名/`（login 用 `docker login` 默认 index.docker.io）
- 注意：`REGISTRY` 只写 **host+路径**，不要带 `https://` 或 `http://`。

#### 3) 在目标服务器拉取并运行（无需源码）
```bash
# 方式 A：用 compose 拉取（最省事）
# 准备一个最小 .env，写入相同的 REGISTRY / TAG / ADMIN_PASSWORD
docker compose pull
docker compose up -d

# 方式 B：纯 docker run（完全不依赖项目文件）
docker run -d --name medical-portal -p 51888:51888 \
  -e ADMIN_PASSWORD=你的强密码 \
  -v medical_data:/app/data \
  registry.example.com/medical/medical-portal:1.0.0
```
> 数据卷 `medical_data` 在目标机上由 Docker 自动创建；首次运行会自动生成 `db.json` 与欢迎内容。

#### 4) 更新版本
```bash
# 构建机：打新标签推送
REGISTRY=registry.example.com/medical/ TAG=1.1.0 ./deploy/build-and-push.sh

# 目标机：拉新版本并重启
TAG=1.1.0 docker compose pull && docker compose up -d
```

#### 5) 安全与排错
- **凭据**：不要在脚本/命令行明文写密码；优先 `docker login` 后凭据存 `~/.docker/config.json`，或用 CI 的 secret。
- **传输加密**：私有 registry 建议启用 HTTPS（或在内网走 TLS 反向代理），避免镜像与密码明文传输。
- **权限**：registry 项目设为私有，仅授权账号可拉取。
- **拉取失败**：先 `docker login` 确认凭据；检查 `REGISTRY` 是否漏了末尾斜杠或多了 `https://`；`docker pull 完整镜像名` 手动验证连通性。
